NovelForge

High-level runtime architecture · current repository-backed view of the reader, creator, authentication, and novel catalog path.

11 core runtime and external components

Primary request path

  • The browser uses the React client, which sends REST requests through Spring Cloud Gateway.
  • The gateway rewrites /api/v1/identity and /api/v1/novels to backend API paths.
  • Identity handles registration and login. Novel handles paginated catalog, search, and novel CRUD.

Ownership and state

  • Identity owns user records in userDB and uses Redis for short-lived OTP and verified-email state.
  • Novel Service owns novel records in novelDB.
  • Compose currently runs both logical databases in one PostgreSQL container. Service ownership does not mean separate DB infrastructure.

Dependencies and deployment

  • Notification Service calls the external Brevo HTTPS API to deliver OTP email.
  • Eureka is configured for service registration and discovery.
  • Compose gateway defaults point at hosted Render URLs unless the service URL variables are overridden.

Scope and trust caveats

  • Engagement, AI, analytics, and studio are scaffolds or in progress; they are not connected to this committed primary request path.
  • Backend services validate authentication. The browser and gateway are not the sole authorization boundary.
  • Repository review found committed sample secrets and token/OTP logging. Novel writes also lack creator ownership checks; address these before production.
